# 游戏活动信息

活动日历里每个活动有两类信息：**时间以数据站为准**（PRTS、B 站 WIKI 等），**进度来自游戏画面**（剩余时间、没做完的事）。

## 回答「有什么活动 / 还剩几天」

1. `game_activities` 看日历。某个游戏的 refreshed 超过半天，先 `game_sites_refresh` 再看。
2. 照日历回答：活动名、还剩几天、商店开到什么时候、还没做完的事。有 `mismatch` 的说明以数据站为准。
3. 游戏包里没有可直接读的数据站（`game_list` 里 auto 都是 false，例如终末地）：用 `web_fetch` 读官网公告页（或 `web_search`），找到活动名和起止时间后 `game_record`（source=site，带上 `url`）。

## 进游戏读进度

只在用户要求、或流水线的 agent 节点要求时做。

1. 先加载这个游戏的技能 `game-<id>`，里面写了从主界面怎么进活动页。
2. `script_runs` 看有没有脚本正在用这个游戏的模拟器或鼠标键盘；有就不要打断，告诉用户等它跑完。游戏没开时不要自己启动它，说明一下就结束。
3. `screen_capture` 截图，按技能里的路线进到活动页。**只看不花**：只打开页面、切换页签、关闭弹窗、返回；不兑换、不购买、不抽卡、不领取要消耗东西的奖励。
4. 每读完一个活动页就 `game_record`（source=screen）：名称照界面原文，`remaining` 照界面原文，没做完的写进 `todo`。这样会保存当时的截图作为依据。
5. 读完回到主界面，用一两句话总结：哪些活动快结束、还有什么没做。

## 日报

每天按「游戏」页里设置的时间自动发到飞书。用户要现在看：`game_report`；要发出去：`game_report`（send=true）。
