# 游戏活动信息

活动日历里每个活动有两类信息：**时间以数据站为准**（PRTS、B 站 WIKI 等），**进度来自游戏画面**（剩余时间、没做完的事）。

## 回答「有什么活动 / 还剩几天」

1. `game_activities` 看日历。某个游戏的 refreshed 超过半天，先 `game_sites_refresh` 再看。
2. 照日历回答：活动名、还剩几天、商店开到什么时候、还没做完的事。有 `mismatch` 的说明以数据站为准。
3. 游戏包里没有可直接读的数据站（`game_list` 里 auto 都是 false，例如终末地）：用 `web_fetch` 读官网公告页（或 `web_search`），找到活动名和起止时间后 `game_record`（source=site，带上 `url`）。

## 进游戏读进度

只在用户要求（例如「帮我去看看有什么活动没做」）、或流水线的 agent 节点要求时做。**有始有终**：一直做到第 7 步，中间不要停下来问「要不要继续」。

1. 先加载这个游戏的技能 `game-<id>`，里面写了从主界面怎么进活动页。
2. `script_runs` 看有没有脚本正在用这个游戏的模拟器或鼠标键盘；有就不要打断，告诉用户等它跑完。
3. 截图看游戏开着没有；没开就 `game_launch` 启动（模拟器里的游戏会先启动模拟器，PC 版用脚本页「启动游戏」里设置的程序）。启动后等它进到主界面：关掉公告、更新提示，启动器要点「开始游戏」就点；要输入账号密码或验证码时停下，告诉用户。`game_launch` 说还没设置程序位置时，告诉用户去脚本页「启动游戏」里设置。
4. 按技能里的路线进到活动页。**只看不花**：只打开页面、切换页签、关闭弹窗、返回；不兑换、不购买、不抽卡、不领取要消耗东西的奖励。
5. 每读完一个活动页就 `game_record`（source=screen）：名称照界面原文，`remaining` 照界面原文，没做完的写进 `todo`。这样会保存当时的截图作为依据。
6. 读完回到主界面，用一两句话总结：哪些活动快结束、还有什么没做。
7. 最后用 `ask_user_question` 问用户要不要把游戏关掉，选项「关掉游戏」「先开着」。游戏是你这次用 `game_launch` 打开的，就把「关掉游戏」放第一个、标签后面加 ` (Recommended)`。用户选关掉就 `game_close`，然后告诉用户已经关了；选开着就结束。第 2 步因为有脚本在用而结束的，不要问、也不要关。
   - 流水线的 agent 节点里没人等着回答：不要问，节点要求里说了关就关，没说就开着。

## 日报

每天按「游戏」页里设置的时间自动发到飞书。用户要现在看：`game_report`；要发出去：`game_report`（send=true）。
